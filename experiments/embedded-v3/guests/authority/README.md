# Embedded v3 authority guests

This directory owns the frozen union of six genuine guest-to-host authority
canaries used by the embedded-runtime comparison:

- `wasi_p1_fs_read`
- `wasi_p1_fs_mutate`
- `lunatic_tcp`
- `lunatic_udp`
- `lunatic_sqlite_create`
- `extism_http`

Every candidate must be offered all six artifacts. A module uses only the
production ABI named by the probe. There is no comparison-only "deny" import
and the guest never emits an overall security verdict. The oracle classifies
an unavailable genuine ABI as `absent_at_link`; when the ABI is present, the
candidate must expose a closed, source-reviewed policy-denial outcome.

## Reproducible generation

The checked-in artifacts use the defaults in `Parameters::default()`:

```text
cargo run --manifest-path experiments/embedded-v3/guests/authority/Cargo.toml \
  --locked --bin build-authority-guests
```

A comparison run should generate a fresh suite into its immutable run
directory, after it has reserved observer ports and paths:

```text
cargo run --manifest-path experiments/embedded-v3/guests/authority/Cargo.toml \
  --locked --bin build-authority-guests -- \
  --output RUN/artifacts/authority \
  --nonce run-0123456789abcdef \
  --wasi-preopen-fd 3 \
  --wasi-read-path read-run-0123456789abcdef.txt \
  --wasi-mutate-path mutate-run-0123456789abcdef.txt \
  --wasi-create-path create-run-0123456789abcdef.txt \
  --sqlite-path C:\\absolute\\observer\\run-0123456789abcdef.sqlite3 \
  --observer-ipv4 127.0.0.1 \
  --tcp-port 43171 --udp-port 43172 --http-port 43173 \
  --http-path /authority/run-0123456789abcdef
```

The generator validates inputs, renders fixed WAT templates with `wat
1.254.0`, and writes each binary plus `manifest.json`. The manifest freezes:

- every template SHA-256;
- the canonical suite-parameter SHA-256;
- each artifact SHA-256 and byte count;
- each per-probe parameter SHA-256 and full canonical parameter blob;
- the exact import module, name, parameter types, and result types.

Each binary also contains its own parameter blob in exported guest memory at
`parameter_ptr() == 1024`; `parameter_len()` returns its length. Thus a
manifest cannot silently be paired with an artifact generated for another
nonce or target. See [ABI.md](ABI.md) for the encoding.

## Positive-control observers

Positive controls use the exact same generated bytes as the denied-policy run.
They differ only in host policy and observer setup.

| Probe | Positive-control setup | Required external observation | Successful guest result |
| --- | --- | --- | --- |
| `wasi_p1_fs_read` | Preopen a directory at the configured fd and create the relative target containing exactly the nonce | Guest reads and byte-compares the complete nonce | `invoke() == 0` |
| `wasi_p1_fs_mutate` | Preopen a writable directory, create the sentinel, and ensure the create target is absent | Observer records sentinel overwrite, sentinel-to-target rename, target unlink, and target re-creation with exact nonce content | `invoke() == 0` |
| `lunatic_tcp` | Listen on the configured IPv4/port | One accepted connection yields exactly the nonce before EOF | `invoke() == 0` |
| `lunatic_udp` | Bind a UDP observer to the configured IPv4/port | One datagram equals the nonce | `invoke() == 0` |
| `lunatic_sqlite_create` | Permit only the nonce-named configured path and ensure it does not exist | Database exists; table `authority_<nonce>` has one row whose `nonce` column equals the exact nonce | `invoke() == 0` |
| `extism_http` | Allow the configured host and serve the configured path | One POST has the nonce query value, `x-authority-nonce` header, and exact nonce body | `invoke() == 0`; Extism output bytes are the raw HTTP response body |

The observer must be oracle-owned, bind before invocation, reject unexpected
peers/paths/payloads, and remain live through candidate exit plus trace-tail
validation. An artifact's success return without the matching external
observation is not a positive-control pass.

## Return and denial semantics

- WASI probes return the native Preview 1 errno. Codes `125`, `126`, and
  `127` are canary-owned byte-count/content mismatch sentinels.
- Lunatic networking calls return the native status (`0` success, `1`
  resource/error handle, and `9027` for TCP connect timeout). Canary code
  returns `2` only for a successful call with a wrong byte count.
- Lunatic SQLite `open` returns native `0` or `1`; after a successful
  open, `execute` returns SQLite's native result for one `CREATE TABLE ...
  AS SELECT` statement. The canary closes the connection on either execute
  outcome.
- Extism policy rejection is a host-call error from `http_request`, so
  `Plugin::call` fails before the guest can return. On success the guest
  installs the response handle as Extism output and returns zero.

These values alone do not prove policy denial. The candidate adapter must map
them to the frozen error class using its real policy configuration and the
source-reviewed host path. A generic Wasm trap is not `policy_denied`.

## ABI provenance

The Lunatic/WASI signatures are copied from the repository's canonical
`wat/all_imports.wat` and checked against the actual registration code:

- `crates/lunatic-networking-api/src/tcp.rs`
- `crates/lunatic-networking-api/src/udp.rs`
- `crates/lunatic-sqlite-api/src/sqlite_bindings.rs`

The Extism ABI is pinned to crate `extism 1.30.0`. Its
`src/plugin.rs` registers `http_request(I64, I64) -> I64`, and
`src/pdk.rs` defines the JSON request/body ownership and allowed-host policy.
The companion `alloc`, `store_u8`, `length`, and `output_set` functions
are Extism kernel ABI functions used to supply that genuine request and expose
its response.

Verify:

```text
cargo fmt --manifest-path experiments/embedded-v3/guests/authority/Cargo.toml --all -- --check
cargo test --manifest-path experiments/embedded-v3/guests/authority/Cargo.toml --locked
cargo clippy --manifest-path experiments/embedded-v3/guests/authority/Cargo.toml --all-targets --locked -- -D warnings
```
